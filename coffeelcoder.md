------------------------------------------------------------------------

## 1. Executive Summary

**Coffeel Coder** is a developer community and technology platform that
connects people through **coffee, code, and community**.

The platform is designed to help developers, students, mentors,
creators, and technology enthusiasts:

-   Learn through articles, guides, and shared knowledge
-   Build and showcase projects
-   Discover mentors and learning opportunities
-   Connect with other developers
-   Discover places suitable for coding, studying, working, meetings, or
    enjoying coffee
-   Submit and review coffee shops and other community-friendly places
-   Create and join developer meetups and events
-   Participate in open-source and community activities

Coffeel Coder should not be positioned as only a blog, coffee-shop
directory, or event website. The long-term opportunity is to create an
ecosystem where people move from:

**Learn → Build → Connect → Meet → Grow**

The core brand idea is:

> **Coffee. Code. Community.**

And the supporting message is:

> **Learn together. Build together. Grow together.**

------------------------------------------------------------------------

# 2. The Problem

Developers and students often have difficulty finding the right
combination of:

-   Practical technology knowledge
-   Experienced people to learn from
-   Developers with similar interests
-   Good places to study or work
-   Reliable coffee shops for coding or meetings
-   Local technology events and meetups
-   Collaboration opportunities
-   Communities where they can build real relationships

Existing platforms usually solve only one part of this problem.

For example:

  Need                      Typical Platform
  ------------------------- --------------------
  Learning                  Blogs / YouTube
  Code                      GitHub
  Professional networking   LinkedIn
  Events                    Meetup / Facebook
  Places                    Google Maps
  Chat                      Discord / Telegram
  Mentorship                Separate platforms

Coffeel Coder's opportunity is to bring these experiences closer
together around a focused developer community.

# 3. The Core Problem Coffeel Coder Solves

# 10. User-Submitted Coffee Shops

This is an important part of the product.

A user can submit a coffee shop they like.

### Submission information

A user can submit:

-   Coffee shop name

# 11. Community Review Workflow

The recommended workflow is:

``` text
User finds a coffee shop
        ↓
User submits the shop
        ↓
Coffeel moderation / verification
        ↓
Shop is approved
        ↓
Shop becomes publicly visible
        ↓
Community members visit
        ↓
Members leave reviews
        ↓
Ratings and experiences accumulate
        ↓
Coffeel can recommend the best places
```

### Roles

  Role           Responsibility
  -------------- -------------------------------------
  User           Submit a place
  Coffeel Team   Moderate / verify
  Community      Visit, review, rate, recommend
  Shop Owner     Eventually claim and manage listing

This creates:

**Submit → Verify → Visit → Review → Recommend → Meet**

# 12. Community Reviews

Coffeel should not rely only on a generic five-star rating.

The review should capture the **purpose and experience**.

Example:

> **John visited Brown Coffee**
>
> Purpose: Coding\
> Duration: 3 hours\
> Wi-Fi: 5/5\
> Noise: 4/5\
> Power outlets: 5/5\
> Seating: 4/5\
> Coffee: 4/5
>
> Comment: "Great place for working. Plenty of outlets and stable
> Wi-Fi."

This makes Coffeel's place data more useful than a generic rating.

``` text
+-- /places
+-- /places/[slug]

+-- /events
+-- /members
+-- /projects
+-- /profile/[username]
```

Do NOT create a separate coffee website yet.

Avoid:

``` text
coffeelcoder.com
coffee.coffeelcoder.com
```

or:

``` text
Coffeel Coder Website
+
Separate Coffee App
```

A separate application would create unnecessary complexity:

-   Multiple frontends
-   Multiple deployments
-   More authentication complexity
-   Split navigation
-   Split SEO
-   Split community
-   More maintenance

The user should experience one product:

> **Coffeel Coder**

Sanity and Supabase are simply different systems powering different
parts of that product.

Do not try to cover every country immediately.

Start with a focused local developer community.

Build a high-quality collection of places in the initial market.

------------------------------------------------------------------------

## Step 2 --- Seed the Platform

Before launch, Coffeel team members and trusted community members can
add a small number of high-quality places.

For example:

-   20--50 useful coffee shops
-   Several detailed reviews
-   Photos
-   Coding/study/meeting ratings

The platform should not launch empty.

------------------------------------------------------------------------

## Step 3 --- Community Contribution

Ask users:

> **"Know a great place to code or study? Add it to Coffeel."**

Make submission extremely easy.

------------------------------------------------------------------------

## Step 4 --- Review Campaign

After visiting a place:

> **"How was your coding session?"**

This is more engaging than simply asking:

> "Leave a review."

------------------------------------------------------------------------

## Step 5 --- Offline Meetups

Start small:

> **Coffeel Coding Session**

One coffee shop.

Five developers.

Two hours.

Then repeat.

The objective is to prove that online Coffeel activity can create
offline relationships.
